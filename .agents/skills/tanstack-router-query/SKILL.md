# Coordinating TanStack Router and Query

## Ownership

- `src/routes/` owns route declarations/composition; `src/features/<feature>/` owns domain behavior.
- `src/app/router.ts` owns the `QueryClient`, router context, and global `Register` type.
- A feature owns its query keys, generated wrappers, mutation invalidation, and tests.
- `src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin; edit route source and let the plugin update it.

## Workflow

1. **Trace the route input.** Identify pathname, params/search values, loader data, and component behavior. **Done when** each input has a typed source and consumer.
2. **Prefetch with context.** Use `context.queryClient.ensureQueryData(...)` in the loader. Prefer generated `get...QueryOptions(...)` so loader and hook share `queryKey` and `queryFn`.
3. **Align keys.** If a feature defines `api/keys.ts`, pass that same key through the generated hook's `query.queryKey` and the loader's generated options. **Done when** both address one cache entry per params.
4. **Keep mutations local.** Wrap generated mutations in `src/features/<feature>/hooks/`; on success invalidate the feature root key. **Done when** affected list/detail queries refresh without route-specific invalidation.
5. **Verify errors and output.** Let unexpected loader errors reach the route boundary; catch only an intentional auth/state branch. **Done when** loader behavior, cache reuse, mutation refresh, generated output, and types are checked.

## Query patterns

For a list route, the shape is:

```typescript
export const Route = createFileRoute('/resources')({
  loader: ({ context }) => context.queryClient.ensureQueryData(getGetResourcesQueryOptions()),
  component: ResourcesPage,
})
```

Use the actual helper name and pass params/search-derived values into both loader and hook. If the feature key is canonical, give generated options the same `query.queryKey`; one cache entry must serve prefetch and render.

For route-driven search, validate the schema and expose values through `loaderDeps`; use those deps to build query options. Keep the component focused on feature hooks and rendering.

## Type safety and generation

- Use `createFileRoute('/path')`; keep the `Register` declaration in `src/app/router.ts` for type-safe links, navigation, and params.
- Add/rename files under `src/routes/`, let the Vite plugin regenerate `src/routeTree.gen.ts`, and inspect Orval helpers before importing them.

## Common traps

| Symptom                            | Fix                                                 |
| ---------------------------------- | --------------------------------------------------- |
| Loader runs but page fetches again | Align the query key/options path in loader and hook |
| Route tree misses a file           | Run the Vite workflow and inspect generated output  |
| Mutation leaves stale data         | Invalidate the owning feature root on success       |
| Loader hides API failures          | Catch only an explicit auth/state branch            |

## Verification map

| Change                               | Check                                     |
| ------------------------------------ | ----------------------------------------- |
| Route, loader, or query behavior     | targeted tests and `bun run typecheck`    |
| Mutation/cache or shared wiring      | targeted tests, then `bun run test`       |
| Generated route or production wiring | `bun run build`, inspect generated diff   |
| Formatting/lint                      | `bun run format:check` and `bun run lint` |
